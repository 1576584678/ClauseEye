## 2. 关键决策

### 2.1 先用"本地 Web 应用"承载 MVP，而不是直接上 Tauri

设计文档推荐 Tauri 桌面壳，但当前开发机只有 `x86_64-pc-windows-gnu` 工具链（无 MSVC），Tauri/WebView2 的 GNU 构建风险高、耗时长。MVP 的目标是先验证**产品闭环**（导入 → 分类 → 坑点 → 对比），因此选择：

- **零后端的纯前端应用**：没有服务端进程，"数据上传"这条路径在架构上不存在，隐私叙事成立且可被用户审计（DevTools 就能看到没有请求）。
- **存储层留出端口**：`src/storage/db.ts` 只有 IndexedDB 的读写原语，业务只依赖 `Vault` 门面（`src/storage/vault.ts`）。迁移到 Tauri 时，只需新增一个 `TauriVaultStore`（rusqlite + SQLCipher）实现同样的读写方法，UI 与核心逻辑不动。
- 代价：依赖浏览器存储，无法接系统钥匙串与系统级通知。这两点列入 v1。

### 2.2 加密方案

- 主密钥：`crypto.getRandomValues` 生成的 256 位随机 AES-GCM 密钥。
- 口令模式：PBKDF2-SHA256（250,000 次迭代）由口令派生 KEK，再用 KEK 包裹（AES-GCM）主密钥后落盘；口令本身不落盘。
- 无口令模式：主密钥明文存于 IndexedDB 的 meta 表（界面上明确标注其安全等级，"仅能防止文件被直接读取"）。
- 每条记录（文档正文 + 分析结果、设置 + BYOK 密钥）单独随机 IV 加密；导出备份时剔除 BYOK 密钥。

### 2.3 OCR 的处理方式（V1 已更新：改用 tesseract.js 离线引擎，详见 `docs/V1实现说明.md` §5）

MVP 为保证"零联网"未内置 OCR 引擎（tesseract.js 的模型需从 CDN 下载，与离线承诺冲突）。策略：

- PDF 若可提取文字层则正常解析；若判定为扫描件（多数页面无文字），在导入结果中明确提示并引导「粘贴文本」。
- 图片格式直接返回降级提示。
- v1 接入 PaddleOCR / PP-Structure 本地模型后即可覆盖该场景。

### 2.4 防幻觉的硬约束（`src/core/analyze.ts`）

BYOK 返回的每条风险必须同时满足，否则丢弃并记录原因：

1. `quote` 必须能在原文中**逐字定位**（`text.indexOf(quote) !== -1`）；
2. 必须给出非空的解释（reason），否则按"三要素缺失"降级；
3. 若该条款已被本地规则命中，则不再重复采纳（保留更可解释的规则结论）。

被丢弃的条目会在提示中展示数量与原因，用户可感知"模型说了什么被我们拦下了"。

### 2.5 规则引擎的分级判定

不做"一刀切"的阈值，而是尽量把法条中的**分级条件**算出来，例如：

- 试用期上限：先由 `extractTermMonths()` 从"自 X 起至 Y 止"推算合同期限，再按劳动合同法第 19 条映射上限（<3 个月→不得约定；<1 年→1 个月；<3 年→2 个月；否则 6 个月）。
- 试用期工资：从同一句里分别取"试用期金额"与"转正金额"（避开"3 个月"这类数字），计算比例后与 80% 红线比较。
- 竞业限制：解析期限（>24 个月即违法）与是否约定补偿，分别给高/中风险。

### 2.6 引用与高亮的实现

所有规则通过 `findMatches()` 返回**原文精确子串**与偏移量，UI 用这些偏移量渲染 `<mark>`。单测专门锁死这一不变量：`text.slice(quoteStart, quoteStart + quote.length) === quote`。这样"引用"永远可回溯，不会出现模型编造条款的情况（BYOK 侧同样受此约束）。

## 3. 与设计文档的差异

| 设计文档 | MVP 实现 | 差异原因 / 后续 |
|---|---|---|
| Tauri（Rust + WebView） | Vite + React + TS 本地 Web 应用 | 见 2.1；v1 迁移，存储层已预留端口 |
| SQLite + SQLCipher | IndexedDB + AES-GCM | 浏览器环境无 SQLite；加密强度同级（AES-256-GCM） |
| PaddleOCR + PP-Structure | 未内置，降级为粘贴文本 | 离线承诺优先；v1 接入本地模型 |
| 到期提醒（本地定时通知） | 提醒页（查看式） | 浏览器无法定时唤醒；v1 桌面端接入系统通知 |
| 本地轻量模型（端侧 GLM 类） | 未使用 | MVP 用规则 + BYOK 已可闭环 |
| `RISK_FLAG.byModel` 字段 | 保留（`RiskFlag.byModel`） | 一致 |
| 人工复核回路 | "确认属实 / 标记误报"仅本地留存 | v1 增加本地改进日志与阈值调参 |
| 数据模型（67 行 ER 草案） | 见 `src/core/types.ts` | 文档内嵌 `AnalysisResult`，少一次 join；字段语义保持 |

## 4. 已知限制

1. 图片 / 扫描件无法直接入库（需粘贴文本或等 v1 OCR）。
2. 规则基于关键词与数值判定，**语义级陷阱（如条款间相互引用造成的矛盾）仍需 BYOK 或人工**。
3. 无口令模式的密钥未接入系统钥匙串。
4. 提醒页不会主动弹出通知。
5. 文档量为"个人级"（数百份）设计：解锁时一次性解密全部记录；海量文档需改为按需解密。
6. 规则库为 v0.1 种子版本，尚未用 LegalBench 类基准量化准确率。

## 5. 下一步建议（优先级排序）

1. **规则库扩充与评测**：把种子规则扩到 150+ 条，建立带标注的评测集（每类 20 份样本），把"召回/误报率"变成可回归的指标。
2. **Tauri 桌面壳**：`TauriVaultStore`（SQLCipher）+ 系统钥匙串 + 系统通知，同时获得离线可信的执行环境。
3. **PaddleOCR 本地推理**：优先覆盖离职证明、工伤鉴定这两类高频图片文档。
4. **BYOK 体验增强**：流式输出、按条款增量展示、调用成本预估。
5. **多设备私有同步**：用户自有云盘（WebDAV / 本地目录）加密同步，保持零持有。
